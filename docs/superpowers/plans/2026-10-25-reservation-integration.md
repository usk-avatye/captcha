# 예약 서비스 연동 구현 계획

**목표:** npm tarball로 설치한 SDK를 예약 화면에 연결하고 PostgreSQL 기록 및 서버 간 인증 확인을 통해 예약을 보호한다.

**설계:** CAPTCHAvatye는 인증, 광고 이벤트, 모의 전환만 소유한다. 고객사 서버가 로그인 사용자와 예약 입력에 묶인 intent를 만들고 비공개 API로 challenge를 발급한다. SDK에는 발급된 challenge만 전달하며 비밀키를 전달하지 않는다. 예약 생성 시 서버 간 확인을 수행하고 intent 소비와 예약을 같은 고객사 DB 트랜잭션에서 저장한다. 동일 intent의 동일 요청은 기존 예약을 반환하고 다른 요청, 사용자, 완료 ID는 거부한다. 예약 실패는 intent 소비도 롤백한다. CTA 이벤트는 필수 조건이 아니다.

**기존 계약:** 공개 인증 API의 응답 및 이벤트 중복 판정은 유지한다. 예약 API의 기존 필드와 응답은 유지하고 captcha 증명을 추가한다. 로그인, Origin, CSRF, 회의실 잠금, 시간 중복 규칙은 유지한다. 기존 참여자 TODO는 이번 범위에서 변경하지 않는다.

**실행 환경:** provider API 8001, 고객사 API 8002, 고객사 Vite 5175. `/captchavatye/api`는 provider, `/api`는 고객사로 전달한다. 이미지 및 선택적 시승 페이지는 provider 프론트엔드 origin에서 제공한다. 기존 DB는 초기화하지 않고 새 전용 `_test` DB 두 개를 사용한다.

- [x] SDK: 선택적 사전 발급 challenge 입력, 단위 테스트, tarball 설치.
- [x] Provider: PostgreSQL 마이그레이션, 원자적 저장, 키로 보호한 발급 및 확인 API, 메모리 회귀와 PostgreSQL 테스트.
- [x] 고객사: intent 마이그레이션, 서버 간 클라이언트, 동일 트랜잭션 소비, 우회 및 동시성 테스트.
- [x] 고객사 화면: 예약하기, 인증, 예약 계속하기, 닫기 및 실패 복구 테스트.
- [x] 실제 두 서버와 브라우저 연동, 서버 재시작 후 재전송, CTA 미참여 검증, 기능별 로컬 커밋.

**검증 초점:** 미인증, 다른 사용자 및 예약 내용, 임의 완료 ID, 중복 ID, 동시 요청, DB 롤백, 서비스 장애, 만료, 서버 재시작, CTA 미참여. 기존 DB, 원격 push, npm 공개는 제외한다.
