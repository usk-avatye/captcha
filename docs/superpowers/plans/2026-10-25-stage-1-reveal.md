# CAPTCHAvatye 첫 연출 구현 계획

> For agentic workers: use superpowers:executing-plans. 사용자가 설계 기반 첫 구현을 승인했으므로 이 단계의 작성·실행·검증을 이어서 수행한다.

## 목표

DESIGN.md의 0~1단계: React + TypeScript + Vite 실행, 세 이미지와 실측 좌표, 임시 성공 버튼으로 램프 스냅 → 동일 차량 원본 줌아웃 → 브랜드·CTA 표시.

## 구조와 제한

- App.tsx는 연출 확인용 호스트, CaptchaModal은 모달 표시와 연출 진행, CarPuzzle은 이미지·좌표·CSS 전환을 담당한다.
- 실제 API·드래그 판정·보상·글 등록·신청은 2~4단계다. 이번 화면에서 성공 ID나 신청 결과를 만들지 않는다.
- 모달 시작 너비 720px, 광고 창 16:9, 스냅 180ms, 공개 650ms. 이미지와 커버는 같은 scene을 사용한다.
- DESIGN.md의 API·상태·ID 계약은 변경하지 않는다. 현재 컴포넌트는 첫 단계 내부 연출 도구이며 SDK 공개 진입점은 후속 연동 때 완성한다.
- 새 지정 폴더에는 Git 저장소가 없고 기존 파일은 DESIGN.md 하나다. 지정 경로에서 직접 작업하고 원격 저장소·배포를 생성하지 않는다.

## 검토할 실패 조건

1. 이미지 준비 실패: 빈 화면을 성공으로 취급하지 않고 재시도할 수 있어야 한다.
2. 연출 중 닫기: 보이지 않는 모달에서 다음 단계로 넘어가지 않고 재열기에 스냅부터 이어야 한다.
3. 완료 후 재열기: 완료 화면 유지, 연출 반복 없음. 다시 보기는 명시적인 초기화다.
4. 작은 창: 모달·CTA가 넘치지 않고 조각·소켓 좌표 정합 유지.
5. 전환 종료 중복·누락: transform 이벤트와 우회 타이머가 단계 전이를 한 번만 수행.

## 실행 결과

Mac에서 단위 테스트 8/8, 빌드, 린트(오류·경고 0), 개발 서버와 세 이미지 HTTP 200을 확인했다. 독립 검토의 로딩 취소·이전 종료 이벤트 문제를 수정하고 재검토했다.

초기 브라우저 연결 경로의 한계는 별도의 Mac headless Chrome 테스트 프로세스로 해결했다. 실제 로컬 앱에서 1280×900 및 390×844의 화면과 9개 시나리오를 검증했고 모두 통과했다. 캡처 검토 중 차량 이미지 재시도 배경 누락과 다시 보기 시 브랜드 문구 잔상을 발견해 회귀 검증·최소 수정 후 다시 통과했다. 기존 Playwright 도구를 재사용했고 프로젝트 의존성은 추가하지 않았다. 결과·캡처·재실행 방법은 루트 README 및 docs/verification/stage1에 있다. DESIGN.md는 변경하지 않았다.
