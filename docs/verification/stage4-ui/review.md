# 4단계 클라이언트 코드 리뷰

- 검토 대상: 선택적 CTA와 이벤트 생성·재시도, 새 탭의 모의 시승 신청, 요청/응답 경계, 오류·수명·중복 처리.
- 기준: DESIGN.md §3, §5, §6, V05~V07 및 기존 API 계약.
- 검토 방식: 별도 검토자가 실제 Mac 소스의 복사본을 읽고 독립 정적 검토. 검토자는 Mac에 쓰거나 브라우저를 실행하지 않았다.
- 검토 소스의 SHA-256: checks.json의 sourceSha256. CarPuzzle의 마지막 한 줄 보완은 별도 후속 검토로 확인했다. 검증 후 네 파일의 마지막 빈 줄만 정리했으며 checks.json에 전후 해시와 범위를 기록했다.

## 발견과 해결

**가운데 버튼으로 CTA를 활성화할 때 cta_clicked가 누락됨.** 기존 링크는 onClick만 연결해 중간 버튼의 auxclick에서 새 탭만 열었다. 실제 Chrome 중간 버튼 테스트에서 새 탭 열기·신청 화면 준비는 성공하고 클릭 이벤트를 기다리는 검증만 실패했다.

CarPuzzle의 같은 링크에 button === 1일 때만 기존 클릭 처리기를 호출하는 onAuxClick을 추가했다. preventDefault·전송 대기를 추가하지 않았고 오른쪽 버튼은 무시한다. 후속 검토에서 수정 적합성을 확인했으며, 브라우저에서 중간 버튼·Enter의 별도 새 ID와 오른쪽 버튼 무시를 포함한 16개 전환 검증이 모두 통과했다.

잔여 수정 지적은 없다. 다른 코드는 이벤트 생성 예외 격리, 4xx/5xx/잘못된 2xx의 재시도 분류, CTA 노출 가드, URL ID 원문, 랜딩 StrictMode, 동결한 신청·정확한 응답 일치, 422/404/409, 원래 포인트·글 등록과의 독립성을 검토했다.

## 검토 중 확인한 경계

- 같은 렌더 전에 재진입한 신청 submit은 같은 선택값을 캡처하고 send의 동기 가드가 두 번째 HTTP를 막는다. 렌더 후에는 sending 상태와 disabled가 적용된다. 서로 다른 pending으로 바뀌는 실제 트리거가 확인되지 않아 추측성 리팩터링은 하지 않았다.
- 성공 응답은 여섯 필드 값과 제출 스냅샷 일치를 검사하고 소비자에게 여섯 필드만 반환한다. 설계에 추가 키 금지 규칙은 없어 추가 필드가 있다는 이유만으로 거절하지 않는다.
- 공개 SDK 입력·콜백·일곱 상태, 서버 네 API와 ID·중복 규칙은 유지한다.

## 실행 증거와 제한

루트 실행자가 Mac의 실제 단일 워커 FastAPI·Vite와 별도 headless Chrome으로 전환 16개, 기존 인증/글 등록 12개, 호스트 6개를 확인했다. 모든 결과와 page error 0은 같은 폴더의 JSON에 있다. 단위 검증은 프론트49개·백엔드152개 통과이며 린트·빌드도 통과했다.

개인 브라우저 프로필·탭은 사용하지 않았다. 모바일 크기는 390×844 emulation이며 실기기·Safari 실행을 의미하지 않는다. 단계5의 현재 UI 서버 재시작·전체 V01~V08 재현을 이 리뷰의 완료 범위로 주장하지 않는다.

## 동시 변경 보존

작업 도중 별도로 들어온 같은 기능의 초안을 읽고 .git 아래 작업용 스냅샷으로 보존한 뒤 통합했다. 검토·검증된 frontend 소스와 이 stage4-ui 증거를 이번 커밋 대상으로 삼는다. 별도로 갱신된 stage3/host-results.json 및 stage4-frontend 자료는 내용을 지우거나 이전 상태로 되돌리지 않는다. 해당 자료의 실행을 이번 결과 수에 합산하지 않는다.
