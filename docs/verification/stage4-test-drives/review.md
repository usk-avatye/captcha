## 결과

**정확성·계약·원자성·동시성·회귀 결함을 발견하지 않았다.** Critical·Important·Minor 수정 사항은 각각 0건이며, 중요한 테스트 누락도 발견하지 않았다.

- 입력 스키마 검증 후 공통 잠금 안에서 클릭 연결과 passed 인증, completionId/clickId 일치를 확인한다. 연결 검증이 기존 신청 비교보다 먼저다.
- 같은 선택은 최초 응답·완료 시각·레코드를 보존하고, 다른 유효 선택은 LEAD_CONFLICT다. CTA·클라이언트 이벤트 수신 조건이 없다.
- leadId는 신청 값의 ID 집합, 내부 eventId는 모든 이벤트 키와 충돌을 확인한다.
- 두 ID·단일 UTC 시각·레코드·응답을 준비한 후 두 맵에 저장한다. 내부 이벤트 생성에서 공통 잠금을 다시 획득하지 않는다.
- 신청 완료 시각과 내부 이벤트의 occurredAt/receivedAt이 같은 시각을 나타낸다. 공개 응답은 정확히 여섯 필드이고 신규201·동일 재전송200을 구분한다.
- 기존 인증·이벤트 코드와 테스트는 변경하지 않았다. 앱 연결 변경은 새 라우터·선택지·신청 저장소로 제한했다.

## 테스트 판단

신규 51개는 실제 HTTP와 저장 상태를 확인한다. 네 선택 조합, 응답 형태, 중복·충돌 보존, 입력 검증 순서, 불완전한 인증 연결, 동일/상이한 동시 요청, 기존 클라이언트/내부 이벤트와의 ID 충돌, 두 번째 ID 생성 실패, 클라이언트 이벤트와 신청의 동시 충돌, 서버 전환 위조 차단, 잠금 밖의 최초 성공 로그를 검증한다.

동시 충돌 시험은 가능한 두 잠금 획득 순서를 모두 유효한 결과로 허용한다. 결정적인 ID 충돌 시험과 덮어쓰기 차단 시험이 이를 보완한다.

## 실행 근거와 제한

Mac에서 백엔드 **152/152**, 신청의 실제 HTTP **13/13**, 이벤트 HTTP 회귀 **9/9**를 실행했다. 독립 검토자는 코드와 이전 버전 diff를 확인했으며, 검토용 환경에 FastAPI·pytest·HTTPX가 없어 테스트를 별도 재실행하지 않았다. 실행 결과와 소스 해시는 checks.json, 실제 신청 결과는 http-results.json에 기록했다.

프론트엔드 CTA·새 탭 신청 화면·이벤트 발행은 이번 검토 범위가 아니다.
