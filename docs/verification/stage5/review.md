# 5단계 검증·문서 리뷰

## 범위와 방법

별도 검토자가 실제 Mac 작업 폴더의 읽기 전용 복사본을 기준으로 DESIGN V01~V08과 기존 테스트·결과를 대응했다. 검토자는 Mac에 접근하거나 테스트를 실행하지 않았다. 루트 실행자가 실제 Mac의 서버·브라우저에서 추가 검증을 수행했다.

기존 백엔드 22개와 프론트엔드 35개 파일, 이전 UI 검증 스크립트 세 개의 일치를 확인했다. 루트는 DESIGN·소재까지 포함해 총 61개 소스/설정/소재 해시가 기준과 같은지 재확인했다. 단계5는 제품 소스를 바꾸지 않는다.

## 발견한 증거 누락과 보완

- 이전 V02 화면은 2단계였으므로 현재 커뮤니티 UI의 오배치·범위 밖·포인터 취소/끝 좌표·리사이즈·잡은 위치/창 크기를 추가 실행했다.
- V04 시작·이미지 로딩 중 닫기와 늦은 결과 전달을 현재 UI에서 확인했다. 검증·연출 구간은 변경 없는 4단계 회귀와 흐름/타이머 단위 결과를 연결했다.
- 기존 이벤트 실패 사례는 원래 글 등록만 확인했고 신청은 하지 않았다. 새로운 context 전체 503 사례에서 노출·클릭·랜딩 전부 실패하면서 실제 신청·원래 글 등록이 성공하는지 확인했다. CTA 탭 복귀 뒤 닫기·재열기도 같은 사례에 포함했다.
- 인증 동시성의 기존 Store 테스트는 in-process HTTP였다. 실제 서버에 barrier로 출발시킨 두 HTTP 요청과 다른 유효 좌표 재전송을 추가해 같은 완료 ID를 확인했다.
- 실제 프로세스 재시작 후 열린 인증/신청 탭의 404, 옛 이벤트/완료 인증의 404, 클라이언트 초기화와 두 번째 전체 시연을 추가했다.

## 검증 코드 검토와 수정

두 브라우저 runner의 독립 정적 검토에서는 구체적인 결함을 찾지 못했다. 성공 API 응답을 만들지 않는지, 실패가 최종 nonzero exit에 반영되는지, 이전 결과/재시작 gate를 잘못 재사용하지 않는지, 필요한 요청·UI·ID 조건이 실제로 검사되는지 확인했다. 재시작 runner에는 서버 프로세스 시작/종료 기능이 없다.

실제 첫 재시작 실행은 업무 확인 항목을 통과했으나 검증용 포인트 관찰 코드가 새 탭에 두 번 주입되어 pageerror 두 건이 발생했다. 루트가 Document별 초기화 가드와 configurable 관찰 속성으로 **검증 코드만** 수정했다. 오류를 필터링하지 않고 실제 서버 재시작을 다시 수행해 **11/11·pageerror 0**을 확인했다. 이전 실패 기록은 작업용 .git gate에 보존했다.

현재 UI 경계 9개도 모두 통과했고, 그 결과와 서버 로그의 ID 연결을 확인했다. 제품 소스의 수정이 필요한 결함은 발견되지 않았다.

## 증거를 읽는 기준

- 브라우저 결과: UI 상태·실제 HTTP·point 이력·요청 payload·ID.
- 실제 HTTP 결과: 별도 연결의 동시 요청과 응답의 재사용.
- 백엔드 Store assertion: lead·서버 전용 전환의 정확한 개수, 시각·기존 객체 보존.
- 서버 로그: 최초 인증·신청의 한 번 기록과 challengeId/clickId/leadId 연결.

브라우저가 내부 메모리 맵을 읽었다고 표시하지 않는다. 기존 49/152/34개 결과를 이번 단계에서 새로 실행한 결과로 표시하지 않는다. 이전 red-* 자료는 수정 전 실패 기록이다.

## 최종 문서 검토

최종 README·coverage·checks와 실제 실행 결과·서버 로그를 대조했다. 실행 수·사례 이름·ID 연결·재시작 정보·근거 파일과 초기화 절차가 일치하며, 새 실행과 기존 검증 재사용 및 브라우저/HTTP/Store assertion의 범위를 구분했다. 수정이 필요한 문서·증거 불일치는 발견하지 않았다. 실제 브라우저 검증은 Chrome headless와 모바일 viewport이며 Safari·모바일 실기기·실제 보상/예약·DB/배포를 포함하지 않는다.
